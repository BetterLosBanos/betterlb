# Local Review Workbench v1

Dev-only review surface for staged OpenLGU legislative documents. Reads local JSONL artifacts, writes append-only review decisions, never touches canonical D1 records.

## Architecture

Two-process design:

- **Vite app**: UI at `/admin/openlgu/workbench`. Route is lazy-loaded with `import.meta.env.DEV` guard at route level to keep workbench code out of production bundles. If not DEV, render "not available in production" instead of the component. Server being down is the runtime gate for dev.
- **Hono server**: `scripts/openlgu/review-workbench-server.mjs` (ESM — Hono is ESM-first, breaking the `.cjs` directory convention intentionally). Reads local JSONL into memory, serves API, appends review decisions. Package script: `"openlgu:review-server": "node scripts/openlgu/review-workbench-server.mjs"`.

Server binds `127.0.0.1:8789` only. CORS restricted to `localhost:5173` / `127.0.0.1:5173`. Env config:

```text
OPENLGU_REVIEW_PORT=8789        # server-side only, not exposed to bundle
VITE_OPENLGU_REVIEW_API=http://localhost:8789  # embedded in client bundle; must never point to non-localhost
```

If `VITE_OPENLGU_REVIEW_API` is unset, the workbench page shows a configuration banner instead of attempting API calls.

## Artifacts

### Read (server loads into immutable memory snapshots)

- `pipeline/openlgu/staged-documents.jsonl` — staged document candidates
- `pipeline/openlgu/staged-person-refs.jsonl` — unresolved person references
- `pipeline/openlgu/reconciliation-shadow.json` — shadow reconciliation report
- `pipeline/openlgu/sources/*/latest/run.json` — source run manifests (consumed by ArtifactStatusBanner for last-scrape-time per source)
- `pipeline/openlgu/source-records.jsonl` — merged source records from all sources (primary lookup target for `source_record_id` resolution)
- `pipeline/openlgu/sources/*/latest/source-records.jsonl` — per-source raw payloads (loaded for evidence display when the merged file lacks detail)
- `pipeline/openlgu/terms.json` — local term snapshot for date inference (see generation step below)

### Term snapshot generation

`pipeline/openlgu/terms.json` does not exist yet. Generated by a new script step:

```bash
npm run openlgu:generate-term-snapshot
```

Runs `scripts/openlgu/generate-term-snapshot.cjs` which queries the local reconciliation shadow and existing config to produce:

```json
[
  { "term_id": "sb_9", "label": "2016-2019", "start_date": "2016-07-01", "end_date": "2019-06-30" },
  { "term_id": "sb_10", "label": "2019-2022", "start_date": "2019-07-01", "end_date": "2022-06-30" },
  { "term_id": "sb_11", "label": "2022-2025", "start_date": "2022-07-01", "end_date": "2025-06-30" },
  { "term_id": "sb_12", "label": "2025-2028", "start_date": "2025-07-01", "end_date": "2028-06-30" }
]
```

If the file is missing, the server starts with an empty term list and term inference returns `unmatched` for all dates.

### Write (append-only)

- `pipeline/openlgu/review-decisions.jsonl` — review decisions

### Load order

Staged artifacts first, then source records, then review decisions, then project review state.

### Reload

File watching triggers reload. Also `POST /api/workbench/reload`. On reload: parse into new snapshot, atomically swap. If parse fails, keep previous snapshot, expose error via `/health`.

## Review Decision Schema

Discriminated by `decision_type`. One decision per source record per field. UUIDv7 IDs for timestamp-sortable history.

```json
{
  "schema_version": "review-decision-v1",
  "id": "rvd_<uuidv7>",
  "source_record_id": "src_res_abc123",
  "staged_document_id": "std_res_def456",
  "source_content_hash": "sha256:...",
  "decision_type": "set_field | cannot_determine | confirm_turnover | ignore",
  "field": "date_enacted | title | term_id | turnover_marker",
  "value": "2023-07-15",
  "derived": {
    "term_id": "sb_11",
    "term_inference": "auto | manual | unmatched"
  },
  "term_override_id": null,
  "term_override_reason": null,
  "evidence": [
    {
      "kind": "pdf_text | website_table_row | facebook_post | filename_inference | manual_inspection | manual_entry",
      "note": "Date visible in PDF header",
      "url": "https://...",
      "local_path": null,
      "quote": "enacted July 15, 2023"
    }
  ],
  "created_at": "2026-05-25T10:00:00Z",
  "created_by": "local"
}
```

### Discriminated shapes

| decision_type | field | value | derived |
|---|---|---|---|
| `set_field` | required | required (string) | computed server-side for `date_enacted` |
| `cannot_determine` | required | null | none |
| `confirm_turnover` | `turnover_marker` | structured object (see below) | `derived.term_id` from turnover context |
| `ignore` | null | null | none |

`confirm_turnover` value schema:

```json
{
  "turnover_marker": "(OLD)",
  "term_id": "sb_11",
  "reason": "election_year_transition | appointment | other"
}
```

- `turnover_marker`: must match the staged document's existing turnover marker
- `term_id`: the outgoing term the record belongs to, validated against `terms.json`
- `reason`: closed enum. `election_year_transition` is the common case for `(OLD)` markers

`derived` for `confirm_turnover`: `derived.term_id` is set from the value's `term_id`. `derived.term_inference` is `"manual"` (turnover assignment is always reviewer-initiated). The normal term inference rules (date-based) do not apply to turnover confirmation.

### Replay durability

`source_content_hash` records what version the reviewer saw. If staged docs are regenerated and hash changes, decision is historical — needs confirmation. If hash matches, carry forward.

## Term Inference

Local term snapshot at `pipeline/openlgu/terms.json`. Not hardcoded, not live D1 query. Generated from canonical data.

Rules when `field=date_enacted`:

- Inclusive ranges: `start_date <= date_enacted <= end_date`
- Exactly one match → `term_inference: "auto"`
- No match → store date, `term_inference: "unmatched"`
- Multiple overlapping → block, surface error
- Boundary + turnover marker → require confirmation

Manual override: `term_override_id` + `term_override_reason`. Server validates term exists.

## Review State and Filtering

Per-field, per-source-record. Derived by server-side projection. Not stored.

States: `active`, `resolved`, `blocked`, `superseded`.

- A row missing both `date_enacted` and `title` stays active in title tab after date is resolved
- Supersession computed in projection: `{ status: "superseded", superseded_by: "rvd_xyz" }`
- History view: all decisions in append order plus projected status
- Filtering: server-side

## API Endpoints (v1)

```text
GET  /api/workbench/health                     # server status, artifact load state, last reload
POST /api/workbench/reload                     # force artifact reload
GET  /api/workbench/stats                      # aggregate counts per tab
GET  /api/workbench/terms                      # local term snapshot
GET  /api/workbench/artifact-status            # generated_at, staged count, decision count, stale/error

GET  /api/workbench/staged-documents           # ?tab=missing_dates&status=active&page=1&limit=50
GET  /api/workbench/staged-documents/:id       # source_record_id lookup
POST /api/workbench/review-decisions           # returns updated projected item state
GET  /api/workbench/review-decisions           # ?source_record_id=src_res_abc123
```

Offset pagination, deterministic sort: active items first, then `document_type ASC, normalized_number ASC, id ASC`. Default tab view uses `status=active`. When status filter is omitted, return all statuses sorted active → resolved → blocked → superseded. Turnover-marked records: include `turnover_marker` in response for UI badge rendering; do not change sort order.

`POST /review-decisions` returns updated projected state so client avoids duplicating projection logic.

## UI Components

```
OpenLguWorkbenchPage
  ArtifactStatusBanner           # generated_at, counts, stale/error
  WorkbenchTabs
    MissingDatesTab              # priority 1 — count derived from loaded artifacts
    MissingTitlesTab             # priority 2 — count derived from loaded artifacts
    TurnoverMarkersTab           # priority 3 — count derived from loaded artifacts
  DocumentReviewPanel            # side panel: evidence + PDF links + form
    SourceEvidencePanel          # raw payload, official URL, mirror, reachability
    ReviewForm                   # field input, evidence kind, note
    ReviewHistory                # decision history with projected status
```

Side panel (not inline, not modal). List stays scannable while panel shows evidence + form.

### PDF link display

- Official URL as primary
- Reachability status badge (reachable/dead/unchecked)
- Local mirror path as secondary
- Truncated display with copy/open controls
- Dead + no mirror = visible blocker state

## Acceptance Criteria

- [ ] Dev-only route exists at `/admin/openlgu/workbench` (lazy-loaded, DEV guard at route level)
- [ ] Local server reads staged-documents, staged-person-refs, reconciliation-shadow, source runs, source records, terms
- [ ] Term snapshot generation script exists: `npm run openlgu:generate-term-snapshot`
- [ ] `pipeline/openlgu/terms.json` produced with valid term date ranges
- [ ] Missing Dates tab lists staged documents with `staging_status=needs_review` and missing `date_enacted`
- [ ] Each item shows type, number, title, source payload, official PDF link, local mirror link when available
- [ ] Reviewer can enter `date_enacted`; UI previews inferred `term_id`
- [ ] Reviewer can save append-only review decision with evidence kind/note
- [ ] Reviewer can mark `cannot_determine`
- [ ] Active list hides rows with latest applicable decision; blocked/history view exposes them
- [ ] No D1 writes occur
- [ ] `npm run build` passes
